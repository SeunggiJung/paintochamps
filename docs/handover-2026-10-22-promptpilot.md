# 인수인계: promptpilot MCP로 타이틀 이미지 예시 만들기 (2026-10-22 · 새 세션용)

새 세션이 가장 먼저 읽는 문서는 `CLAUDE.md`(§0)이고, 그다음 이 문서다. **UI 리디자인 구현은 끝났다**(상세·결정 원문은 `docs/handover-2026-10-22-redesign.md`, 이 문서의 §5에 요약). 이 문서는 그 뒤 사용자가 새 세션을 연 **이유**와 지금 상태를 다룬다.

## 0. 새 세션이 가장 먼저 할 일

1. `CLAUDE.md` → 이 문서 순서로 읽는다.
2. **사용자의 첫 메시지는 아래 §1의 할 일에 대한 답/재요청일 수 있다.** "다시 해줘", "아까 그거", "만들어봐" 같은 짧은 말이면 §1로 해석해 바로 진행한다. 이미 확정된 것(§3)은 다시 묻지 않는다.
3. 결정된 것은 이 문서 §3에 즉시 기록하고, 새 인수인계 문서를 만들면 `CLAUDE.md` §0의 "지금 최신"을 함께 고친다.

## 1. 지금 해야 할 일 (사용자 요청 그대로)

> "방금 추가함 promptpilot 이용해서 타이틀 이미지 예시 만들어볼래? **괜찮으면 쓰려고**"

- **promptpilot MCP 서버로 타이틀 장면 이미지 예시를 만들어 사용자에게 보여 준다.** 사용자가 마음에 들어 하면 실제 게임에 쓴다. 마음에 안 들면 지금 있는 이미지를 그대로 둔다(현재 이미지는 이미 적용·커밋돼 있어서 급하지 않다).
- 이 요청이 새 세션을 연 이유다: **MCP 서버는 세션 시작 때 불러오므로 이전 세션에서는 도구가 보이지 않았다.**

### promptpilot에 대해 확인한 것 / 못 한 것
| 항목 | 내용 |
|---|---|
| 추가 방법 | 사용자가 `claude mcp add promptpilot -- npx -y promptpilot-mcp` 실행을 요청해 내가 실행했다. **로컬 범위**(`C:\Users\tmdrl\.claude.json`의 `paintochamps` 프로젝트)에만 있다. `claude mcp list`에서 `✔ Connected` 확인 |
| 패키지 | npm `promptpilot-mcp` 1.2.1, 설명 "MCP server for PromptPilot.club — generate images, video, and audio via Pollinations API", 배포자 `rickai`, 저장소 `github.com/doctorm333/promptpilot-mcp-server` |
| **도구 이름·인자** | **아직 모른다.** 이전 세션에서 `ToolSearch("promptpilot")`이 아무것도 못 찾았다. 새 세션에서 먼저 `ToolSearch`로 `promptpilot`(또는 `mcp__promptpilot`)을 검색해 도구 목록·스키마를 확인한다. 도구가 안 보이면 `claude mcp list`로 연결을 보고, 그래도 안 되면 사용자에게 `/mcp`로 서버 상태를 확인해 달라고 한다 |
| 신뢰도 | 제3자 패키지(`npx -y`로 매번 최신을 받아 실행). 사용자는 출처를 확인하라는 안내를 받았다. 이상한 동작이 보이면 멈추고 알린다 |
| 이용 조건 | Pollinations 생성 이미지의 **상업적 이용·고지 의무를 확인하지 못했다**(리디자인 Q3와 같은 문제). 쓰기로 정하기 전에 사용자에게 확인을 부탁하고, 필요하면 서비스 소개 페이지(`src/data/site.json`/`src/ui/infoPages.ts`)에 "AI로 만든 이미지" 문구를 넣는다 |

### 만들 때 지킬 것
- **CellCog는 더 쓰지 않는다**(크레딧 사유, 남은 약 192). 이미지 예시는 promptpilot으로만 만든다.
- **같은 구도 4장면**: 방구석 → 훈련 → 대회 → 우승. 다른 장면을 원하는지는 아직 사용자에게 안 물었다(이전 세션에서 질문했고 답은 못 받음) — 필요하면 한 번만 묻는다.
  - 방구석: 노을 지는 방, 의자에 앉아 모니터를 보는 게이머, **양손이 키보드에 닿는** 자세(예전 도트 장면의 '손이 떠 있는' 문제 해결), 벽 포스터·빈 트로피 선반·침대 위 고양이·컵라면·LED
  - 훈련: 코치·팀원과 함께 연습하는 장면(모니터 불빛 여러 곳, 창밖 노을)
  - 대회: 두 팀이 **서로 마주 앉은 구도**(상대 팀 얼굴이 보이고 모니터는 뒷면), 한쪽 5명이 모두 보이게, 조명 빔·야광봉 관중
  - 우승: 트로피·폭죽·종이 조각
- 현재 이미지의 그림체는 "촘촘한 도트풍 + 일반 비율"이다. 게임 속 2.5등신 스프라이트와는 다르다는 알려진 한계가 있다. **새 예시는 기존 4장과 나란히 비교**해 사용자가 고르게 한다(시안으로 보여 주기를 매우 좋아하는 사용자다: 아래 §6).
- **화면에 코드로 올리기 전에 먼저 예시(파일)만 보여 준다.** 사용자가 정하기 전에는 `src/`를 건드리지 않는다(과거에 시키지 않은 작업을 해서 크게 혼난 적이 있다).
- 이미지 변환(크기·형식)은 내가 다른 도구로 하지 않는다. 사용자가 https://anypictoanypic.com/ko/ 로 한다. 아래 §4의 설정을 안내한다.

## 3. 이미 정해진 것 / 사용자가 직접 한 것

- **타이틀 이미지 4장은 사용자가 변환해서 폴더에 넣었고 커밋까지 됐다**: `src/assets/title/scene-1-room.webp`·`scene-2-train.webp`·`scene-3-match.webp`·`scene-4-win.webp`, 각 900×598. 4장이 **모두** 있어야 슬라이드가 켜진다(하나라도 없으면 옛 도트 장면). 원본은 CellCog로 만든 `docs/redesign-mockups/title-cellcog-1.png`·`-2-train.png`·`-3-match-v2.png`·`-4-win.png`.
- 파일 크기: 장당 약 600~900KB(합계 약 3MB). 계획했던 100~200KB보다 크다. **품질을 82 → 70 정도로 낮춰 다시 변환하면 줄어든다.** 새 이미지로 교체할 때 함께 제안한다(필수는 아님).
- 타이틀 슬라이드 동작: 16초 주기, 장면당 4초, 천천히 줌, 장면별 CSS 효과(LED·김·별 / 모니터 불빛 / 조명 빔·야광봉 / 폭죽·종이), 자막 4줄(방구석에서 열심히 게임하던 겜돌이가 → 코치·팀원과 연습해서 실력을 키워 → 대회에서 다 같이 겨루고 → 월드 챔피언을 향해!). 차분(calm) 움직임이면 효과·줌이 꺼지고 우승 장면 하나만 고정. 코드는 `src/ui/titleScene.ts`(`titleHero`·`buildHero`·`sceneUrls`).
- **이미지를 새것으로 교체하는 방법**: 같은 파일 이름·같은 비율(3:2, 900×598)로 `src/assets/title/`에 덮어쓰면 코드 수정 없이 반영된다. 비율이 다르면 `.hi-frame { aspect-ratio: 3 / 2 }`(`titleScene.ts`의 `HERO_CSS`)와 효과 좌표(퍼센트)를 조정해야 한다. **효과 좌표는 지금 이미지의 구도(모니터·창문 위치)에 맞춰져 있어서**, 구도가 다른 이미지를 쓰면 효과가 어긋난다 → 새 이미지를 쓰기로 하면 `effects()`의 퍼센트 좌표를 새 구도에 맞춰 고친다(시안 `docs/redesign-mockups/20-title-4scenes.html`에 원래 좌표가 있다).

## 7. 사용자 스타일·규칙 (CLAUDE.md §9와 메모리에도 있음)

- 한국어. **응답 맨 끝에 "이번 턴에 한 작업"**(변경 파일·검증·커밋·노션·미수행) 요약을 붙인다.
- **시킨 것만 한다.** 모호하면 추측으로 실행하지 말고 되묻는다. 한 번에 하나씩.
- **시안(눈으로 볼 수 있는 결과물)으로 보여 주는 것을 매우 좋아한다.** 이미지 예시는 파일로 만들어 Edge로 열어 보여 주거나, 기존 이미지와 나란히 놓은 HTML 시안(`docs/redesign-mockups/`에 새 파일 이름으로)으로 보여 준다. 파일 이름을 재사용하지 않는다.
- 결정된 것은 **즉시 이 문서에 기록**한다. 서브에이전트는 사용자가 요청할 때만, 푸시도 요청할 때만, 커밋은 작업 단위마다(접두사 `feat/fix/docs/...`, 끝에 시스템이 알려 주는 `Co-Authored-By` 줄).
- 결과를 부풀리지 않고 실패·한계를 그대로 말한다. 확인 못 한 건 확인 못 했다고 쓴다.
- 이미지 변환은 사용자의 사이트로(§4). Claude가 ImageMagick·PIL로 변환하지 않는다.
- 데이터 JSON을 스크립트로 통째로 다시 쓰지 않는다. Bash 한 번에 heredoc 여러 개를 섞지 않는다(셸 파싱이 깨진다) — 파일 생성은 Write 도구로.
