## 우선순위

**P1 — 지금 톤과 가장 어긋나고 가장 눈에 띄는 것**
1. **A 내 방 배경 6장**: 홈 탭에 계속 보이는데 지금은 어두운 파란 도트라 새 타이틀과 가장 안 맞는다. **사람이 없는 빈 방 이미지**라 신체 뒤틀림 문제가 없어 가장 쉽다. 캐릭터는 지금처럼 스프라이트를 얹는다(의상 변경 유지). 책상 소품 10종은 코드로 유지하거나 방 이미지에 맞춰 위치만 조정.
2. **B 엔딩 일러스트 12장**: 판의 감정 정점이고 결과 카드로 공유된다. 임시 그림이 가장 미완성. 묶음: ① 핵심 4장 = `legend`·`hidden_loyal`·`world_finalist`·`pro1_regular` ② 우승 변형 4장 = `goat`·`emperor`·`two_time`·`owner`(legend 무대에 트로피 수만 다름 → 같은 프롬프트에서 트로피 수만 바꿔 뽑는다) ③ 나머지 = `pro2_veteran`·`coach`·`streamer`·`hobbyist`. 인물은 뒷모습·측면, 3:2(1200×800 → 변환 900×598).

**P2 — 쓰임은 적지만 손쉽게 완성도를 올리는 것**
3. **C 도감 잠긴 썸네일 1·배너 1** (A·B와 같은 톤의 "?" 실루엣 카드, 트로피 선반 배너).
4. **D 공유용 대표 이미지 1장**(1200×630): 타이틀 방구석 이미지를 크롭해 재사용 가능 → 새 생성 없이 변환만. `index.html`에 `og:image`·`og:title`·`og:description` 추가 필요(코드 작업).

**P3 — 노출이 드물거나 이미지로 바꾸기 어려운 것**
5. **E 결승 중계 2장**: 5대5 + 모니터 문제(모델이 인원·모니터를 못 지킴)가 있어 어렵다. 배경 이미지 + 기존 CSS 효과(교전·승패 환호) 조합이 현실적. 타이틀 대회 장면 재사용도 가능.
6. **F 광고 촬영 6장**: 카테고리별 배경만. 프로 1부 후반에만 본다.
7. **G 계약 연출 1장**: 팀 색이 바뀌는 연출이라 이미지로 바꾸려면 팀 색 오버레이가 필요. 필요성 낮음.

**유지 권장 (이미지로 바꾸지 않음)**
- **H 장비·시설 그림**(13종 × 5단계): 44px 작은 아이콘이고 단계마다 색·부품이 자동으로 바뀌는 구조라 AI 이미지로 만들면 65장 이상이다. 유지.

## 구현 방식 (타이틀과 같은 파이프라인)

- 이미지는 사용자가 anypictoanypic.com에서 WebP로 변환해 폴더에 넣고, 코드는 `import.meta.glob`으로 있는 것만 쓴다(타이틀의 `sceneUrls` 방식). **이미지가 없으면 기존 SVG를 그대로 쓴다**(점진 교체 가능).
- 엔딩: `ending.ts`의 `endingArt`가 `data-art="ending_<id>"` 자리에 `endingSceneSvg(id)`를 넣는다. 이미지가 있으면 `<img>`/배경으로 바꾼다. 화면 비율은 지금 hero 16:10·썸네일 96×60 → 3:2 원본을 `object-fit: cover`로 맞춘다. 파일 위치 `src/assets/endings/ending-<id>.webp`.
- 내 방: `roomSceneSvg`가 만드는 SVG 배경을 방 이미지로 바꾸고 스프라이트·책상 소품을 위에 얹는다. 파일 위치 `src/assets/rooms/room-<id>.webp`, 좌표(책상·의자 위치)는 이미지마다 정해야 한다.
- 용량: 장당 70~140KB(품질 70~82) 목표. 12+6장이면 약 2MB. 엔딩·방은 첫 로딩에 안 쓰이게 필요할 때만 불러온다.
- 이용 조건(AI 이미지 상업 이용·고지)은 아직 확인 못 했다 → 쓰기로 굳히기 전에 확인하고, 필요하면 서비스 소개 페이지에 "AI로 만든 이미지" 문구를 넣는다.

## 진행 순서 제안

1. A 내 방 배경 6장 시안(빈 방, 같은 구도) → 사용자 승인 → 변환·적용.
2. B-① 엔딩 핵심 4장 → B-② 4장 → B-③ 4장(각 단계마다 시안 승인).
3. C·D, 그다음 E·F·G는 필요하다고 정해질 때.
