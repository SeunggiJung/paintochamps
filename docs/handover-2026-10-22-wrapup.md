# 인수인계: 2026-10-22 마무리 (타이틀 이미지 교체 + UI 마감 점검 · 새 세션용)

새 세션이 가장 먼저 읽는 문서는 `CLAUDE.md`(§0)이고, 그다음 이 문서다. 이 날의 앞선 흐름은 `docs/handover-2026-10-22-promptpilot.md`(이미지 방향 결정 기록 §1-1)와 `docs/handover-2026-10-22-redesign.md`(UI 리디자인 결정 원문)에 있다.

## 0. 지금 상태 (한 줄)

UI 전체 리디자인 구현과 타이틀 이미지 교체, 마감 점검 수정이 모두 끝나 `master`에 푸시됐다. 남은 큰 일은 **사용자 직접 플레이 확인**이고, 이미지 교체 범위("전부")는 타이틀 4장만 끝났다. 사용자가 "굳이 안 해도 되는 것"으로 정리한 항목은 §3에 있다.

## 1. 오늘 한 일 (요약)

- **UI 전체 리디자인**: 하단 탭 4개, ⚙ 설정(테마 3·글자 3·움직임 3·소리), 시즌 계획 2단계 전체 화면, 시즌 결산 탭과 제안 게이트, 엔딩 한 화면+탭, 도감, 팝업 5종류, 상황별 가이드 15종. (구현은 앞선 세션, 오늘 점검)
- **타이틀 이미지 4장 교체**: promptpilot MCP의 `gptimage`로 만든 노을빛 도트풍 4장(방구석·훈련·대회·우승)을 사용자가 900×598 WebP로 변환해 `src/assets/title/`에 넣었고, `src/ui/titleScene.ts`의 `effects()` 좌표를 새 구도에 맞췄다(머리 까딱 복제본·전구·컵라면 김·고양이 zzz·조명 빔·응원봉·키보드 불빛·폭죽 등).
- **마감 점검 수정**: PC 폭에서 타이틀 그림·홈 '내 방' 그림이 너무 커지던 것(폭 상한), 시즌 계획 방침 설명 한 줄화(전체는 `?` 가이드), 지출 카드 가로 배치와 '구매' 문구 삭제, 선수 탭 장비 현황 2열, 계획 소개 문구 정정, 시설 설명 한 줄화, `.choice.with-art`·`.choice.offer`가 세로로 쌓이던 CSS 버그, 시설 탭 하단 버튼 줄바꿈.
- **시즌 종료 화면 정리**: 시험 준비를 고를 일이 없는 시즌은 시즌 종료 화면 없이 바로 결산으로(`app.ts` `toSeasonEnd`). 시험이 있는 시즌만 `seasonEnd.ts` 화면이 남는다.
- **엔딩까지 플레이 점검**: 코드로 자동 진행시켜 1~15시즌(16~30세) → 구단 인수 선택 → 구단주 엔딩 → 엔딩 탭·도감·명예의 전당까지 확인했다.
- 푸시 완료, 테스트 547개·`tsc`·빌드 통과. 노션 작업일지·트러블슈팅·메인 페이지 갱신.

## 2. 이미지 작업 방법 (다음에 다시 만들 때)

- **promptpilot MCP**(`claude mcp add promptpilot -- npx -y promptpilot-mcp`, 로컬 범위). 세션을 새로 열어야 도구가 보인다. 이미지 생성 결과 URL은 **API 키가 있어야 내려받아진다**(키 없이는 401): `Authorization: Bearer <키>` 헤더로 받는다. 키는 사용자가 발급(https://enter.pollinations.ai/keys)해 주고, **저장소·메모리·문서에 적지 않는다**. 지금 쓴 키는 채팅에 노출됐으니 **폐기하고 새로 발급받길 권한다**.
- **MCP가 알려 주는 모델 목록이 서버와 안 맞는다**: `gptimage`만 확실히 동작했고 `imagen-4`·`klein-large`·`grok-video`는 400(Invalid model). 서버 모델 목록(`/v1/models`)에 영상 모델이 없어 **영상 생성은 불가**.
- **통한 프롬프트의 핵심**: `detailed pixel art game illustration, MapleStory-like style, characters about 3.5 heads tall with slightly large heads, dot eyes, crisp outlines, romantic dreamy golden hour atmosphere, glowing peach-orange walls ..., floating sparkles, hopeful nostalgic mood, vivid saturated colors, no text` + 장면 묘사. `enhance:false`, 1200×800, 시드 바꿔 여러 장 뽑아 고른다. 캐릭터는 **뒷모습 구도**로 신체 뒤틀림을 피한다.
- **퇴짜 맞은 톤**: 칙칙한 갈색(너무 어두움), 일반 비율(귀여운 맛 없음), chibi(너무 귀여움). 승인된 톤 = "3.5등신 중간 + 석양빛".
- 대회 장면은 "선수마다 모니터 1대 + 5대5"를 둘 다 만족시키지 못했다(모델 한계). 확정 이미지는 모니터 우선, 4대4로 보인다.
- 승인된 시안·이미지: `docs/redesign-mockups/27-title-4scenes-pp.html`, `title-pp-rom-1-room.jpg`·`-2-train`·`-3-match-b`·`-4-win`, `26-title-room-anim.html`. 나머지 후보 이미지는 의도적으로 추적하지 않았다.
- 이미지 변환은 사용자가 https://anypictoanypic.com/ko/ 로 한다(900×598 WebP, 품질 70~82).

## 3. 남은 일 (사용자가 "굳이 안 해도 된다"고 한 것 포함, 우선순위 낮음)

사용자가 마지막에 "다 굳이 안 해도 되는 것들"이라고 정리한 항목:
- **조사 자동 처리**: 문구에 "은(는)"·"이(가)"가 그대로 나온다(엔딩 `{name}은(는)` 등 8곳 이상, 엔진 메시지, 팝업). 받침을 보고 맞추는 함수를 만들어 적용하면 된다.
- **엔딩 이름 칩 스포일러**: 30세 결산 화면에 "엔딩: 프로 1부 주전 은퇴"가 미리 보인다(도감은 못 본 엔딩을 숨기는 방침과 어긋남).
- 시간 흐름 연출 뒤 `visibility:hidden` 팝업이 DOM에 남는다(화면엔 안 보임).
- 결과 카드·결승 중계·대회 결과 카드, 구단주 외 엔딩 화면은 점검하지 못했다.

그 밖의 남은 일:
1. **사용자 직접 플레이 확인**(시즌 계획 길이·홈 밀도·테마·PC 패널 — 오늘 샘플로 점검해 문제를 고쳤다).
2. **나머지 이미지 교체(범위 "전부")**: 엔딩 일러스트 12종(`docs/ending-images.md`, 지금은 코드로 그린 도트 SVG) → 결승 중계·계약·광고 촬영·내 방·장비/시설 그림 순으로 제안. 같은 톤·프롬프트(§2)로 만든다.
3. **이미지 이용 조건 확인**: Pollinations 생성 이미지의 상업 이용·고지 의무를 확인하지 못했다(리디자인 Q3와 같은 문제). 쓰기로 굳히기 전에 확인하고 필요하면 서비스 소개 페이지에 "AI로 만든 이미지" 문구를 넣는다.
4. API 키 폐기(채팅에 노출됨).
5. `public/도메인.png`는 사용자가 "그냥 무시"하라고 했다(추적하지 않음).

## 4. 점검 방법 메모 (다음에 화면을 코드로 훑을 때)

- 개발 서버 `npm run dev`(`http://localhost:5173/`)를 Playwright로 열고, 버튼을 텍스트로 찾아 `evaluate`로 클릭하면 빠르다(MCP 클릭의 ref는 화면이 바뀌면 낡는다). 장면 애니메이션은 `document.getAnimations().forEach(a => { a.pause(); a.currentTime = N })`으로 시간을 고정해 스크린샷한다.
- 자동 진행 드라이버(브라우저 안에서 반복): 팝업(`[role=dialog]`, `style.visibility !== 'hidden'`인 것만), 이벤트는 첫 선택지, 계획 화면은 첫 훈련 선택 → '다음 · 지출 계획' → '이 계획으로 시즌 시작', 결산의 '제안' 탭에서 `.choice.offer` 선택 → 'N시즌 시작', 끝은 '결과 카드 만들기' 문구로 판정. `position: fixed` 요소는 `offsetParent`가 null이므로 `getClientRects().length`로 보이는지 판단한다.
- 화면 확인은 모바일(390×844)·PC(1280×800)·테마 3종을 본다.
