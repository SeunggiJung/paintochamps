# 인수인계: UI 전체 리디자인 (2026-10-22 · 구현 완료, 사용자 직접 플레이 확인 대기)

새 세션이 가장 먼저 읽을 것은 `CLAUDE.md`이고, 그다음 이 문서다. 어제 문서(`docs/handover-2026-10-21.md`)는 구단 시장·경력·업적 상점 작업, 이 문서는 **그 뒤에 시작한 UI 전체 리디자인**(브레인스토밍 → 설계 문서 → 구현 계획까지 끝남)을 다룬다.

## 0. 새 세션이 가장 먼저 할 일 (필독)

사용자가 **컨텍스트를 초기화하거나 새 대화창을 열면**, 아래 순서를 **다른 어떤 작업보다 먼저** 한다.

1. `CLAUDE.md` → 이 문서(§0·§1) 순서로 읽는다. 가장 최근 날짜의 `docs/handover-*.md`가 이 문서다.
2. **사용자의 첫 메시지는 §1의 '대기 중인 질문'에 대한 답일 수 있다.** 사용자는 "이전 창에서 받은 질문에 새 창에서 답할 수 있게 써 두라"고 했다. 첫 메시지가 짧거나 맥락 없이 "Native로 시작", "그걸로 가자", "1번" 같은 말이면, §1의 대기 중인 질문 목록과 맞춰 보고 **그 답으로 해석해서 이어 간다.** 어느 질문에 대한 답인지 애매하면 되묻되, 이미 §2의 확정 사항에 있는 것은 다시 묻지 않는다.
3. 이전 대화의 결정은 전부 §2(확정 사항)와 `docs/superpowers/specs/2026-10-22-ui-redesign-design.md`에 있다. 대화 기록이 없어도 이 둘로 충분히 이어진다.
4. **사용자가 시안으로 정한 것은 그 즉시 이 문서에 기록한다**(§9). 이 문서를 최신으로 유지하는 것이 다음 새 창이 이어지는 유일한 방법이다.
5. 일을 마칠 때마다 §1의 '지금 상태'와 '대기 중인 질문'을 갱신한다.

## 1. 지금 어디까지 왔나

**단계: 구현(계획서 Task 1~24)이 끝났다. 사용자 직접 플레이 확인과 타이틀 이미지 4장 배치만 남았다.** 사용자가 Q1에 "Native로 시작"이라 답해 이 세션에서 계획서 순서대로 직접 구현했다(작업 단위 커밋, master, **푸시는 안 함**). 테스트 548개 통과, `npm run build` 통과, 봇으로 튜토리얼 한 판(뽑기→시즌 12회→엔딩) 끝까지 돌려 콘솔 오류 0개 확인.

**구현 중 내린 판단(Ruling)**: ①테마 대비 기준(≥3/4.5)을 못 넘는 색 3개를 조정(light `--muted`·`--up`, cozy `--accent-text`; 이유는 `theme.css` 주석) ②탭 목록 클래스는 `.segmented`(기존 `.seg`는 능력치 변화 그래프용) ③홈 탭 첫 접속 가이드·`GameSession`은 계획서대로 ④시즌 계획 ① 화면은 방침 설명이 길어 한 화면보다 길다(글자 축소로 완화) ⑤cinema 팝업의 `title` 칩은 넣지 않았다(스킵 버튼 위치만 CSS로 고정) ⑥`finished` 상태로 `toHome`이 불리면 타이틀로 보낸다 ⑦가이드 12종 문구는 CLAUDE.md의 규칙에서 확인해 작성 ⑧`home.ts`·`planScreen.ts` 삭제.

**사용자가 구현 단계에 대해 정한 것** (2026-10-22)
- **작업 브랜치 없이 `master`에서 작업한다.** 다만 `master`에 push하면 Cloudflare Pages가 자동 배포하므로 **push는 계속 사용자가 요청할 때만** 한다. 커밋은 작업 단위마다.
- **구현은 한 번에 이어서 진행한다**(단계마다 멈춰서 확인받지 않는다). 막히거나 시안에 없는 큰 결정이 필요할 때만 묻는다.
- **CellCog(AI 이미지)는 타이틀 4장 외에는 더 쓰지 않는다**(크레딧 사유, 남은 약 192). 새 그림이 필요하면 기존 도트 그림 재사용 또는 CSS·SVG.

## 3. 내가 제안했고 사용자가 아직 명시적으로 확인하지 않은 것 (제 추측)

> **최신 목록은 설계 문서 §7**(`docs/superpowers/specs/2026-10-22-ui-redesign-design.md`)과 §1의 Q4다. 아래는 브레인스토밍 초기에 적은 것이고, 이후 확정된 항목(탭 이름·내용, 팝업 시트 방식 등)은 §2로 옮겨졌다.

- 하단 탭 이름과 나누는 기준: 🏠홈(상태·확인할 일·방 그림·다음 턴 진행) / 📅시즌(일정 타임라인·시즌 계획 요약과 '계획 바꾸기'·다른 팀 성적) / 🧑선수(능력치·장비·시설 업그레이드·내 경력) / 🏆기록(도감·업적·업적 상점·명예의 전당·설정). **탭 구조 자체는 "좋을 것 같다"고 했지만 이름·기준은 시안만 보고 동의한 상태**다.
- PC 패널 폭 약 800px(킥루 값을 참고한 추측).
- 기기의 "동작 줄이기(prefers-reduced-motion)"가 켜져 있으면 움직임을 자동으로 "차분" 수준으로.
- 한 번 직접 고른 테마·글자·움직임이 자동 설정보다 우선하고, 설정에 "자동"으로 되돌리는 항목을 둔다.
- 모바일 팝업(이벤트·턴 결과·대회 결과 등)을 지금의 가운데 카드 대신 **아래에서 올라오는 시트**로 바꾼다. 아직 확인받지 못했다.
- 테마와 글자는 서로 독립(예: 테마 C + 갈무리).
- 하단 고정 바는 큰 버튼 하나("다음 턴 진행") + 작은 버튼 3개로 줄인다.

## 5. 다음에 할 일

브레인스토밍에서 안 정했던 것들은 **모두 정해졌다**(§2). 남은 것은 §1의 '대기 중인 질문'과 **구현 계획서(`docs/superpowers/plans/2026-10-22-ui-redesign.md`)의 24개 작업**이다. 작업 순서 요약: 토대(설정 로직·가이드 기록·테마 토큰·글자·팝업 종류·부품·PC 패널: Task 1~6) → 셸·설정 시트·`GameSession`·탭 4개·도감(7~12) → 시즌 계획 2단계·시즌 종료·결산 탭·엔딩·시작 흐름(13~18) → 팝업 분류·가이드·업데이트 로그·타이틀 4장면·움직임 3단계(19~23) → 마감(24).

계획을 쓰며 코드에서 확인한 것(실행자가 알아야 함):
- **입단 테스트 준비(`testPrep`)는 결산을 계산하기 전에 골라야 한다**(`settleSeason`이 합격 여부에 반영). 그래서 결산의 '제안' 탭이 아니라 결산 직전 **'시즌 종료' 전체 화면 단계**(Task 14)에 둔다. 설계 문서는 정정했다(`7f9a90d`).
- 팝업은 지금 **전부 가운데 카드가 기본**이다(`sheet.ts`의 `center`). 종류별로 나누는 건 Task 5(variant 추가)와 Task 19(분류·필수화).
- `home.ts`(494줄)에 상태·턴 진행·협상·이적이 한 클로저로 뭉쳐 있어 **`GameSession` 추출(Task 9)이 가장 위험한 작업**이다. 화면이 달라지지 않는 순수 리팩터로 먼저 한다.
- UI 테스트용 DOM 환경이 없어서 Task 1에서 `happy-dom`을 개발용으로 추가한다. 글자 3종은 npm 패키지(`pretendard`·`@fontsource/jua`·`galmuri`, 존재 확인함)를 번들해 직접 서빙한다(개인정보처리방침과 맞추려고 외부 CDN 금지).
- Task 10과 11은 **연속으로** 해야 한다(홈에서 연봉 협상·이적 요청 버튼을 뺐다가 선수 탭에 다시 만들기 전까지 접근이 끊기지 않게).

## 6. 일정 추정 (사용자에게 말한 것)

테마 3개 포함 전 화면 리디자인은 **약 7~10 작업일**(하루 4~6시간 기준)로 말했다. 준비 0.5 + 토대(토큰·공통 컴포넌트) 1~1.5 + 핵심 화면 2~3 + 나머지 화면 2~3 + 마감 1. 테마를 3개로 늘려서 하나만 만들 때보다 1~1.5일이 늘었다. 확인 횟수와 방향 변경이 일정을 가장 크게 흔든다.

- 켜져 있을 수 있는 프로세스: 개발 서버 `localhost:5173`(백그라운드 vite), 시안 서버 `localhost:54139`(4시간 유휴 시 자동 종료, 종료는 `stop-server.sh <세션 디렉터리>`). 새 세션에서 안 쓰면 꺼도 된다.

- 추적하지 않는 파일 `public/도메인.png`는 사용자가 둔 것이라 커밋하지 않았다(처리 방법은 사용자에게 물어볼 것).

Python SDK(`cellcog` 2.6.0)를 `py -3 -m pip install --user cellcog`로 Python 3.12에 설치했고, API 키는 사용자가 `setx CELLCOG_API_KEY ...`로 **사용자 환경 변수**에 넣었다(**키 값은 이 문서에 쓰지 않는다**). 키는 이전 대화 기록에 노출됐으니, 우려되면 https://cellcog.ai/profile?tab=api-keys 에서 재발급해 교체하도록 사용자에게 권한다. 새 터미널·새 창에서 `setx` 값은 읽히지만, 이미 열려 있던 프로세스에는 안 보여서 `[Environment]::GetEnvironmentVariable('CELLCOG_API_KEY','User')`로 읽어 쓴다. 첫 이미지 대화 id는 `6ad938fd976ca9e40ef4a045`. **남은 크레딧 약 192.** 앞으로 더 쓰지 않기로 했다.
- **사용자 확인용 브라우저는 Edge**: 시안·화면을 보여 줄 때 `Start-Process msedge "<경로 또는 URL>"`로 열어 준다(사용자 요청). 내가 직접 조작·캡처하는 브라우저는 Playwright(크롬 계열)이고, 이건 시안 확인용으로도 같이 쓴다.
- 개발 서버 `npm run dev`(`http://localhost:5173/`)가 백그라운드로 켜져 있을 수 있다. 시안 HTML은 `http://localhost:5173/docs/redesign-mockups/<파일>`로도 열린다.
- 스크래치 스크립트(시안 생성기 `make*.py` 등)는 세션의 scratchpad에 있어 **새 세션에는 없다.** 시안 HTML 자체는 `docs/redesign-mockups/`에 커밋돼 있으니 필요하면 그걸 고친다.

## 9. 사용자 스타일 메모

- 한국어, 결과는 요약해서 말해 달라는 편이고 "이번 턴에 한 작업" 요약을 매 응답 끝에 붙인다(`CLAUDE.md` §9).
- **시안으로 보여 주는 방식을 매우 좋아한다**("와씨 개좋은데?"). 말로 설명하기보다 시안을 먼저 보여 주고, 둘 이상을 비교할 때는 나란히 놓고, 결과는 직접 열어 눈으로 확인한 뒤 말한다.
- 레퍼런스(킥루)를 정확히 베끼기보다 "참고해서 더 다듬고 꾸미라"는 방향이고, 선택지를 하나로 좁히기보다 **여러 개를 설정으로 고를 수 있게** 하는 걸 선호한다(테마·글자·움직임).
- 솔직한 한계 설명을 허용하고 오히려 정확한 설명을 원한다(도트 그림 수준 질문에 한계를 말했을 때 좋은 반응).
- **시안으로 보여 주고 사용자가 정한 것은 그 즉시 이 인수인계 문서에 기록한다**(2026-10-22 사용자 지시: "어떻게 하기로 결정한 거는 무조건 바로 인수인계에다가 넣어놔"). 다음 질문이나 시안으로 넘어가기 전에 먼저 기록한다.
- **시킨 것만 한다.** 2026-10-22에 "사람이 부자연스럽다"를 얼굴·그림체 전면 재작업으로 넘겨짚고, 시키지 않은 타이틀 장면 교체·업데이트 로그 수정·커밋 시도까지 해서 크게 혼났다(작업은 전부 롤백했다). 모호하면 추측으로 실행하지 말고 먼저 되물을 것. 지적이 "손이 키보드에서 떨어져 있다"처럼 구체적이면 **그 점만** 고친다. 한 번에 하나씩 차근차근.
- **(2026-10-22 갱신)** 설계는 승인됐으므로 구현 단계에서는 `src/`를 수정해도 된다. 단 **구현 계획서를 사용자가 확인한 뒤(Q1 답)** 시작한다. (이전 규칙: 설계 승인 전에는 코드를 건드리지 않는다 — HARD-GATE.) 시안은 `docs/redesign-mockups/`의 독립 HTML로만 만든다. 화면 확인은 Playwright 브라우저로 직접 열어 캡처·클릭해 본 뒤 보여 주고, 사용자 확인용으로 Edge에서도 연다(`Start-Process msedge`).
- 이름 취향: 돈을 쓰는 화면 이름은 '돈 쓰기'보다 **'지출 계획'**.
- **사용자는 컨텍스트를 자주 초기화하거나 새 창을 연다.** 그래서 새 세션은 반드시 이 문서를 먼저 읽고(§0), 사용자의 첫 답을 §1의 대기 중인 질문에 맞춰 해석한다. 이 문서가 최신이 아니면 다음 창이 흐름을 잃는다.
- **서브에이전트는 사용자가 요청할 때만 쓴다**(시스템 규칙). 설계 문서의 '빌더 확인'도 내가 빌더 입장에서 직접 읽어 점검했다. 사용자가 원하면 그때 서브에이전트로 한다.
- 사용자는 **"한 번에 이어서" 진행하는 걸 좋아하고**, 결정은 짧게 한다("1번", "그대로 가자"). 질문은 한 번에 모아서 묻고 추천을 먼저 말한다. 시안은 Edge로 열어 달라고 했다.
