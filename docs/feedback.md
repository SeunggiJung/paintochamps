### 설계 메모 (2026-10-16 사용자 결정)

**3번 훈련 교체** (구현 완료 — 아래는 결정 당시 메모. 실제 규칙은 CLAUDE.md §6)
- 훈련은 시즌 단위로 정하고 턴 동안에는 웬만하면 바꾸지 않는다.
- 시즌 중 **성적이 안 좋다고 판단되면 코치가 교체를 제안**하고, 그때 선택지가 뜬다(받아들이면 그중 고른다). 처음엔 무작위였지만 2026-10-18부터 부족한 능력치를 채우는 훈련 순으로 보여 준다.
- 구현 전에 정할 것: 훈련 몇 개를 고정하는지, "성적이 안 좋다"의 기준(중간 순위? 승률? 컨디션?), 코치가 없는 방구석·초반 루트에서의 대체(가족·친구 조언 등), 제안 빈도 한도, 밸런스 재측정.

**10번 업데이트 로그**
- 대상: 최초 배포일(2026-10-15) 이후 바뀐 모든 것. `git log`에서 정리한다.
- 접속하면 메인(타이틀)에 업데이트 로그 팝업이 뜬다. **최신 업데이트만 펼쳐져 있고 나머지는 접혀 있다.**
- 닫기와 **"오늘 하루 안 보기"** 를 둔다(`localStorage`에 날짜 저장, 저장소 접근 실패해도 동작해야 한다).
- 데이터는 `src/data/` JSON(날짜·제목·항목)에 두고 코드 수정 없이 추가한다. 타이틀에서 다시 볼 수 있는 버튼도 둔다.
- 앞으로는 사용자에게 보이는 변경을 할 때마다 로그 항목을 함께 추가한다.

### 같이 요청받은 UI 변경 (완료)
- 턴 진행 바의 "예상 효과" 줄 제거. 시즌이 끝난 뒤 최종 수치를 확인하는 방식으로.
- 턴 결과·이벤트 결과·시즌 결산의 능력치 변화를 그래프로: 기존(파랑)·증가(초록)·감소(빨강) 색을 나눈 막대와 `기존 → 현재 +증가량` 수치 (`ui/turnResult.ts`).

## 2. 우선순위 (2026-10-16 제안)

기준: 게임이 끝까지 돌아가야 하는가 > 플레이 피로·이탈에 직접 영향 > 몰입 > 규모 대비 효과.

1. ~~④ 엔딩 화면·도감·이어하기~~ — **구현 완료(2026-10-16), 직접 플레이 확인 대기.** 엔딩 화면·도감·업적·자진 은퇴 버튼·다시 뽑기 횟수 표시, 엔딩 일러스트 8장(코드로 그린 도트 SVG, 퀄리티는 이후 개선).
2. ~~3번 훈련 시스템 개편~~ — **구현 완료(2026-10-16), 직접 플레이 확인 대기.** 시즌 훈련 고정 + 코치 교체 제안. 난이도는 재측정해 국제전 상대 990→1000, 튜토리얼 성장 1.05→1.08로 조정했다.
3. **11번 시즌 결산 활약 시스템** — 몰입 효과가 크다. 엔딩 화면과 같은 결산 화면군이라 1번 직후가 효율적이다. 엔진에 경기 기록·시상 데이터를 만든다.
4. **5·6번 콜업·계약·연봉 협상** — 하나의 계약 시스템으로 묶어서 설계한다. 기존 승급 구조를 건드리는 큰 작업.
5. **7번 돈 소비처** — 5·6(연봉)이 들어오면 돈 흐름이 바뀌므로 그 뒤에 조정한다.
6. **10번 업데이트 로그** — 작고 쉽다. 사양이 정해졌고 기준일은 2026-10-15. 틈날 때 먼저 해도 된다(빠른 성과).
7. **8번 해외 리그** — 4단계. 리그 순위 집계부터 필요해 규모가 크다.


빠른 성과 후보: 10번(로그). 사용자 확인 대기: 정밀 모드 예상 제거가 의도에 맞는지, 훈련 고정 뒤 난이도 느낌과 코치 제안 기준(`rules.coachSwap`)이 적절한지(직접 플레이).
