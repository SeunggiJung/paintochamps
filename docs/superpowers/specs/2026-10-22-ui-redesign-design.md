# UI 전체 리디자인 설계 (2026-10-22)

「방구석 겜돌이에서 프로게이머되기」의 **모든 화면을 새 디자인으로 다시 만드는** 작업의 설계 문서다. 이 문서만 읽고도 구현 계획을 세울 수 있도록 썼다. 근거가 되는 대화·시안·결정 기록은 `docs/handover-2026-10-22-redesign.md`(결정의 원문)와 `docs/redesign-mockups/`(시안 HTML, 아래 §10)에 있다. 프로젝트 전체 규칙은 `CLAUDE.md`가 먼저다.

**표기**: **[사용자]** = 사용자가 직접 정했거나 시안을 보고 확정한 것. **[제 판단]** = 작성자(Claude)가 정한 것으로 사용자가 명시적으로 확인하지 않았다. 읽으면서 틀린 것을 고쳐 주길 바란다.

## 1. 의도와 이유

- 지금 UI는 1인 개발로 기능을 쌓아 가며 만들어서 **"배경이 너무 칙칙하고 버튼도 배치도 대충 만든 티가 난다"**(사용자 말). 엔딩 화면 8,479px, 도감 4,775px, 시즌 계획 시트 3,893px, 후반 시즌 결산 3,329px처럼 **한 열로 끝없이 이어지는 화면**이 많고, 홈 하단 고정 바가 화면의 약 30%를 차지한다(`docs/redesign-baseline.md`).
- 목표는 "처음 보는 사람이 어디에 뭐가 있는지 알 수 있고, 한 판(15~25분)을 모바일에서 편하게 끝까지 하는" 완성도다. 레퍼런스는 **킥루(kickru.com)** — 밝은 회색 배경, 흰 둥근 카드, 하단 큰 파란 버튼, 점 단계, 아래 시트 — 를 참고하되 "더 다듬거나 꾸며도 된다"고 했다. **[사용자]**
- 게임의 성격(방구석에서 시작하는 도트·메이플풍 성장담)은 그대로 둔다. 그래서 도트 스프라이트·일러스트·장면 그림은 **유지**한다.

## 2. 목표 · 비목표 · 안티 목표

**목표**
1. 모든 화면을 하나의 디자인 체계(색·모서리·그림자·글자·간격·움직임)로 통일한다.
2. 긴 화면(엔딩·도감·시즌 계획·시즌 결산)을 탭·접이식·단계로 나눠 **한 화면에 한 가지 일만** 보이게 한다.
3. **테마 3종**(밝은 카드 A · 크림+도트 B · 다크 C), **글자 3종**, **움직임 3단계**를 설정에서 고를 수 있게 한다.
4. 기능이 처음 나오는 화면마다 짧은 가이드를 **처음 한 번만** 띄운다.
5. 타이틀 화면을 새 이미지 4장면으로 바꾼다.

**비목표** (이번 작업에서 하지 않는다)
- **엔진·규칙·수치·밸런스 변경.** `src/engine`, `src/data/*.json`의 규칙은 건드리지 않는다. **[사용자]**
- 새 게임 기능 추가(시즌 중 계획 변경, 대회 참가 결정 등). 화면 구조만 바꾼다. 장비·시설 구매는 지금처럼 **시즌 시작 시에만** 한다. **[사용자]**
- 도트 캐릭터·소품·엔딩 일러스트·결승 중계 장면의 **그림 자체를 새로 그리는 일.** (타이틀의 4장면만 예외.) **[사용자]**
- 프레임워크 도입. UI는 지금처럼 **바닐라 TypeScript**다. `CLAUDE.md`의 구조 규칙(엔진은 UI를 임포트하지 않는다 등)을 지킨다.
- 온라인 기능, 로그인, 서버 통신.

**안티 목표** (기술적으로 돌아가도 실패로 보는 것)
- 기존에 있던 **정보·기능이 안 보이거나 접근할 수 없게 되는 것**(퇴행). 새 구조에서 어디로 갔는지 §6의 표로 항상 추적할 수 있어야 한다.
- **필수 선택을 건너뛰는 길**이 생기는 것(시즌 결산의 입단·이적 제안 고르기 전에 다음 시즌으로 넘어가기 등).
- 360px 모바일 세로 화면에서 **가로 스크롤**이 생기거나 버튼이 화면 밖으로 나가는 것.
- 기존 세이브가 못 읽히는 것(세이브 호환을 깬다).
- 개인정보처리방침과 어긋나는 **외부 서버 호출**(예: 외부 글자 CDN) — §4 제약 참고.

## 3. 사용자가 정한 것 (확정 사항)

세부 문구와 근거는 `docs/handover-2026-10-22-redesign.md` §2. 여기는 구현자가 알아야 할 결정만 모은다.

### 3.1 디자인 체계
| 항목 | 결정 |
|---|---|
| 테마 | **A 밝은 카드**(회색 배경·흰 카드·파란 포인트) / **B 크림+도트 테두리**(크림 배경·굵은 갈색 테두리와 아래 그림자·주황 포인트) / **C 다크**(남색 그라데이션·반투명 카드·보라/파랑 포인트). **기본은 기기 설정을 따라 다크면 C, 아니면 A.** B는 직접 고른다. 테마와 글자는 서로 독립이다. **[사용자]** (독립이라는 점은 [제 판단]) |
| 글자 | 기본 **Pretendard**, 선택 **주아(Jua)**·**갈무리(Galmuri)** **[사용자]** |
| 움직임 | 기본 **보통**, 선택 **차분·화려** **[사용자]**. 기기의 "동작 줄이기"가 켜져 있으면 자동으로 차분 수준 **[제 판단]** |
| 설정 | 모든 화면 오른쪽 위 **톱니바퀴 ⚙ → 아래에서 올라오는 설정 시트**(테마·글자·움직임·소리·업데이트 로그·가이드 모아 보기·타이틀로) **[사용자]** |
| PC | **가운데 패널에만 게임을 채우고 양옆은 배경만 비운다** **[사용자]**. 패널 폭은 약 800px **[제 판단, 킥루 값 참고]** |
| 모바일 우선 | 360px 세로 화면을 먼저 맞춘다(`CLAUDE.md`) |

### 3.2 화면 구조
**육성 중 = 하단 탭 4개** **[사용자]**
- 🏠 **홈**: 상태(컨디션·돈·명성), 내 방 그림(안에 '상점·꾸미기 ›'), 이번 시즌 일정 요약, 방침·훈련 칩, 하단 큰 **'다음 턴 진행'** 버튼(탭 바 바로 위). 연봉 협상이 가능할 때만 '연봉 협상 가능' 칩.
- 📅 **시즌**: 일정 타임라인, 이번 시즌 계획 요약(**보기만**), 다른 팀 성적.
- 🧑 **선수**: 능력치(`?` 도움말), **계약 카드(연봉 협상·이적 요청)**, 장비·시설 현황(**보기 전용**), 내 경력.
- 🏆 **기록**: 도감, 업적 상점, 명예의 전당.
- 시안 `25`가 테마별 상세. 탭 이름·내용은 시안을 보고 확정됐다.

**탭 바 없는 전체 화면** **[사용자: "B로 가자"]**: 타이틀, 캐릭터 만들기, 뽑기, **시즌 계획(① 계획 → ② 지출 계획)**, **시즌 결산**, **엔딩**, 연출 화면. 화면 아래에는 시작/다음 버튼 하나만 둔다. 끝나면 홈으로 돌아가 탭 바가 다시 나타난다.

**긴 화면의 새 구조**
- **엔딩 화면** — 한 화면 + 접이식: 위에 그림·이름·문구, 업적·토큰은 한 줄 요약(+전체 보기), 기록은 **요약/수상/구단/시즌별** 세그먼트 탭(시즌별은 한 줄 타임라인, 오래된 시즌은 접기). 하단 고정 버튼 '결과 카드'·'타이틀로'. 시안 `07`·`08`.
- **도감** — 위에 '3/12 발견'과 진행 막대, 세그먼트 **엔딩/업적/명예의 전당**. 엔딩·업적은 **타일(2열)·리스트(1열) 두 보기, 기본 타일**, 전환 버튼 ▦ ☰는 **톱니 바로 아래**, 고른 보기는 저장. 명예의 전당에서는 전환 버튼 숨김. 타일을 누르면 아래 시트로 상세. 못 본 것은 조건을 숨긴 `???`. 시안 `09`·`10`.
- **시즌 계획** — 두 단계(점 단계). ① **계획**(방침 2×2 카드·훈련 후보 4개·개인 레슨 스위치) → ② **지출 계획**(세그먼트 **장비/시설/광고/집**, 항목을 누르면 기존 업그레이드 팝업) → '이 계획으로 시즌 시작'. 이름은 **'지출 계획'**("돈 쓰기" 아님). 시안 `11`.
- **시즌 결산** — 한 화면 + 탭: 맨 위에 큰 결과 카드(예: '월드 4강'), 아래 세그먼트 **성적/성장/정산/제안**. **제안** 탭에 입단·이적 제안(필수 선택)·연봉 협상·이적 요청. 결정이 남은 탭에는 **빨간 점**, **필수 제안을 고르기 전에는 어느 탭에서도 하단 시작 버튼이 막힌다**('제안을 골라 주세요'). 시안 `12`.
  - 시안에 없는 것의 배치 **[제 판단]**: 제안 탭에는 입단 제안뿐 아니라 **콜업·이적·해외 이적·백지수표 제안**도 같은 카드 모양으로 나온다(제안 종류가 달라도 '카드 하나를 고른다'는 흐름은 같다. 입단·콜업은 필수, 이적·해외·백지수표는 거절 가능). 초반 루트의 **입단 테스트 결과·준비 선택**(`testPrep`, 준비를 안 고르고 넘어가면 확인 시트)도 결정이 필요한 항목이라 제안 탭 안에 둔다. **'여기서 은퇴하기'**(자진 은퇴, 튜토리얼에서는 월드 우승 전까지 없음)는 제안 탭 맨 아래 '커리어 마무리' 항목으로 둔다. 진로 문구(`routeNotes`)·시즌 한 줄 요약은 성적 탭 맨 위, 광고 정산·리그 파워 랭킹·시즌 활약(평점·수상)은 정산/성장 탭에 둔다.
- **시작 흐름** — 타이틀(큰 버튼 '새로 시작', 저장된 판이 있으면 '이어하기'가 큰 버튼·'새로 시작'은 보조, 엔딩 도감·업적 상점·업데이트 타일 3개, 약관 링크·권리 고지는 작게) → **캐릭터 만들기는 한 화면**(이름·장르·모드 + 하단 '능력치 뽑기') → **뽑기**(하단 버튼 '다시 뽑기'(보조)·'이 캐릭터로 시작'(주), '원하는 등급까지 뽑기'는 카드 아래 링크로 여는 시트, '처음부터'는 ‹ 뒤로). 뽑기 연출은 지금과 같다(능력치 0.13초 간격 → 특성 → 0.35초 뜸 → 등급 공개 + 테두리 빛 + SR 이상 폭죽, 카드 눌러 건너뛰기, 자동 뽑기 2배속·멈추기, 횟수는 카드 아래 안내 줄). 시안 `16`·`17`.

### 3.3 팝업 4종류 **[사용자: "좋은 거 같은데?", 대회 결과는 가운데]** (시안 `15`)
1. **결정**(이벤트 선택·이적/콜업 제안·확인·연봉 협상·장비/시설 업그레이드·시험 준비 확인): **아래에서 올라오는 시트**, 바깥을 눌러도 안 닫힘(지금과 같음).
2. **결과**: **대회 결과 카드는 지금처럼 화면 가운데 카드**(폭죽·효과음 그대로). 턴 결과·이벤트 결과는 **아래 시트**(가볍게). 대회 '중간 순위'는 대회 결과 계열이라 가운데 카드 **[제 판단]**.
3. **정보 보기**(내 경력·다른 팀 성적·상점·꾸미기·업적 상점·업데이트 로그·밥사주기·결과 카드): **큰 아래 시트**, ✕ 또는 아래로 끌어서 닫기.
4. **연출**(시간 흐름 진행·결승 중계·계약·광고 촬영·미니게임): **탭 바 없는 전체 화면 + 스킵 ⏩**(미니게임은 '건너뛰기'), 위 스코어보드/제목·가운데 8:5 도트 장면·아래 멘트/자막/HUD. **연출 틀도 선택한 테마를 그대로 따른다**(어둡게 통일하지 않음, 사용자 결정, 시안 `24`).

### 3.4 가이드 **[사용자]** (시안 `21`·`22`)
- **첫 접속 가이드 5단계**: 소개 → 지금 상태 → 다음 턴 진행 → 아래 탭 4개 → 설정. 시즌 1 첫 턴에 자동으로 뜨고 설정에서 다시 본다(기존은 소개·상태·능력치·시즌 계획·턴 진행 5단계였으나 구조가 바뀌어 교체).
- **상황별 가이드**: 기능이 처음 나타난 화면마다 **처음 한 번만** 짧게(3~4줄). 이후는 항목 옆 `?`와 설정의 **'가이드 모아 보기'**(본 것 ✓ / 아직 안 본 것 빨간 글씨)로 다시 본다. 사용자가 정한 범위는 "필요한 곳 다"이고, 시안으로 확인한 것은 ①시즌 계획 ②지출 계획 ③연봉 협상·이적 요청 ④입단·이적 제안. 더해 붙일 후보(**[제 판단]**, "다"라는 말에 따라 전부 넣는 방향): 첫 이벤트 선택, 첫 부상·슬럼프, 입단 테스트 준비, 첫 턴 결과·컨디션 단계, 시즌 중 이적·콜업 제안, 광고 제안, 집과 가족, 상점·꾸미기, 업적 상점, 결승 중계·미니게임 첫 등장.
- 본 기록은 주제별로 저장한다(지금은 `MetaSave.guideDone` 하나뿐).
- **업데이트 로그**: 큰 아래 시트 **하나만** 스크롤(지금의 이중 스크롤 해소), 날짜는 접이식·최신만 펼침, 하단 '닫기'·'오늘 하루 안 보기', 타이틀의 '업데이트' 타일과 설정에서 열림.

- **순서: 방구석 → 훈련 → 대회 → 우승**(기존은 방구석 → 대회 → 훈련 → 우승). 16초 주기로 장면이 부드럽게 넘어가고, 장면별 **CSS 효과**(방구석: LED·모니터 불빛·김·별·노을·고양이 숨쉬기 / 훈련: 모니터 불빛 / 대회: 조명 빔·야광봉 / 우승: 폭죽·종이 떨어지기)와 천천히 다가가는 줌. 영상(AI 영상 루프)은 쓰지 않는다. 시안 `20`이 기준이다.
- 자막 4줄: "방구석에서 열심히 게임하던 겜돌이가 → 코치·팀원과 연습해서 실력을 키워 → 대회에서 다 같이 겨루고 → 월드 챔피언을 향해!".
- 알려진 한계: 게임 속 2.5등신 스프라이트와 그림체가 다르고(타이틀에만 쓴다), AI 그림이라 정확한 도트 격자가 아니다.

## 4. 제약

- **기술 스택**: Vite + TypeScript, 바닐라 DOM(`h()` 헬퍼), 서버 없는 정적 웹. `package.json`의 의존성을 늘리는 건 최소화한다. 규칙·수치는 `src/data/*.json`, 엔진은 UI와 분리된 순수 함수(`CLAUDE.md` §3).
- **외부 요청 금지**: 개인정보처리방침이 "서버로 수집·전송하지 않는다"고 말한다(`src/ui/infoPages.ts`). 따라서 **글자(Pretendard·주아·갈무리)는 저장소에 포함해 직접 서빙**해야 하고 외부 CDN·구글 폰트를 쓰지 않는다. 라이선스(Pretendard·Jua·Galmuri는 오픈 폰트 라이선스)와 파일 크기를 구현 때 확인한다. 이미지·소리도 외부 호출 없이 번들한다.
- **세이브 호환**: `GameState`·`MetaSave`에 필드를 더하면 옛 세이브에서도 동작해야 한다(`createInitialState`·도우미 기본값). 설정(테마·글자·움직임·고른 보기)과 가이드 본 기록은 `MetaSave` 또는 별도 localStorage 키로 두고 `try/catch`로 감싼다 **[제 판단, 위치는 빌더가 정함]**.
- **접근성**: 키보드 포커스, `aria-live`(뽑기 결과), `prefers-reduced-motion` 존중(지금 코드에 있음).
- **테스트**: 지금 440개 테스트(`npm test`)가 계속 통과해야 한다. UI는 엔진 테스트에 영향이 없어야 한다. 새 화면 상태(탭 전환·가이드 본 기록·테마 저장)는 테스트할 수 있는 순수 함수로 분리한다.
- **이미지 용량**: 타이틀 이미지 4장은 각 2.6~3.8MB라서 **가로 약 900px WebP(품질 80~85)로 줄여** 넣는다. 변환은 사용자가 만든 사이트(https://anypictoanypic.com/ko/)로 하고, 쓸 설정(형식·크기·품질)을 사용자에게 안내한다(`CLAUDE.md` §9). Claude가 다른 도구로 변환하지 않는다.
- **배포**: `master`에 push하면 Cloudflare Pages가 자동 배포한다. 푸시는 **사용자가 요청할 때만**(`CLAUDE.md` §9). 미완성 UI가 자동 배포되지 않게 작업 브랜치를 쓰는 방안을 §8에서 묻는다.
- **업데이트 로그**: 사용자에게 보이는 변경은 `src/data/updates.json`에 날짜별 한 항목으로 추가한다(`CLAUDE.md` §6).
- **작업 방식**: 한국어, 작업 단위마다 커밋(`feat/fix/docs/...`), 응답 끝에 "이번 턴에 한 작업" 요약, 노션 기록(`CLAUDE.md` §9).

## 5. 빌더에게 맡기는 것 (구현 판단)

사용자가 따로 정하지 않았고 결과 화면이 §3과 시안에 맞기만 하면 빌더가 정해도 되는 것들이다. 정한 것은 문서·커밋에 남긴다.

- 디자인 토큰을 **CSS 변수**로 두는 구조(테마·글자·움직임을 `data-` 속성으로 전환), 공통 컴포넌트(카드·칩·세그먼트·시트·점 단계·하단 탭·말풍선)의 분리 방식.
- 탭 전환·전체 화면 전환의 라우팅 방식(주소 해시 `#/…`는 이미 정보 페이지가 쓴다. 충돌하지 않게).
- 설정 저장 위치·키 이름, 가이드 본 기록의 키 이름, 기기 설정(다크/동작 줄이기) 감지 방법.
- 글자 파일을 어떻게 서빙·분할(서브셋)할지, 이미지 4장의 `<img>`/CSS 배경 방식, 장면 전환 애니메이션 구현(CSS 키프레임 등).
- **구현 순서**. 아래는 **[제 판단] 제안**일 뿐이다.
  1. 토대: 토큰·테마 3종·글자·움직임·설정 시트·PC 패널
  2. 앱 셸: 하단 탭 바와 전체 화면 전환
  3. 탭 4개 화면(홈·시즌·선수·기록)
  4. 전체 화면 흐름: 타이틀·만들기·뽑기·시즌 계획 ①②·시즌 결산·엔딩·도감
  5. 팝업 4종류와 연출 틀
  6. 가이드(첫 접속·상황별·모아 보기)와 업데이트 로그 시트
  7. 타이틀 이미지 4장면과 효과
  8. 마감: 기준선(`docs/redesign-baseline.md`)과 화면별 비교, 360px·PC 폭 점검, 테스트, 업데이트 로그
- 시안에 없는 세부(빈 상태·오류 문구·로딩·긴 이름 처리 등)는 시안의 분위기에 맞춰 정한다.

## 7. 아직 사용자 확인이 없는 가정 (읽고 틀리면 알려 줄 것)

- 테마와 글자는 독립. 기기 "동작 줄이기" 시 차분 수준 자동 적용. 한 번 직접 고른 테마·글자·움직임이 자동 설정보다 우선하고 설정에 "자동"으로 되돌리는 항목을 둔다.
- PC 가운데 패널 폭 약 800px.
- 대회 '중간 순위' 카드는 가운데 카드.
- 시즌 결산에서 시안에 없던 항목의 배치(§3.2의 "시안에 없는 것의 배치"): 입단 테스트 준비·콜업/이적/해외/백지수표 제안·'여기서 은퇴하기'를 제안 탭에 둔다.
- 설정 시트에 **소리 켜기/끄기**가 들어가면 지금의 오른쪽 위 🔊 둥근 버튼은 없어진다(⚙ 하나로 통합). 사용자는 "모든 화면 오른쪽 위 톱니"만 정했고 🔊의 운명은 말하지 않았다.
- 상황별 가이드의 추가 후보 10곳(§3.4)은 "다"라는 말을 근거로 전부 넣는 쪽으로 가정했다.
- 타이틀 애니메이션은 시안 `20`의 CSS 효과(A안)로 확정으로 간주했다. 사용자가 영상 루프(B안)를 따로 고르지 않았다.
- 대회 장면 이미지는 각 팀이 4명씩만 선명하게 보이고 5번째는 가려져 있다(사용자가 이대로 가자고 함).
- **AI 생성 이미지의 이용 조건**: CellCog 약관상 상업적 이용·고지 의무를 확인하지 못했다. 타이틀 이미지를 게임에 넣기 전에 사용자가 확인하고, 필요하면 서비스 소개 페이지에 "AI로 만든 이미지" 문구를 넣는다.

## 8. 구현 시작 전 질문과 사용자 답 (2026-10-22, 승인으로 간주)

사용자가 아래에 답하고 "구현 한번에 이어서 하자"고 해서 **이 설계를 승인한 것으로 보고 구현 계획 단계로 넘어간다.**

1. **작업 브랜치: 쓰지 않는다. `master`에서 작업한다.** **[사용자: "브랜치 - master로 가자"]** 다만 `master`에 push하면 Cloudflare Pages가 자동 배포되므로 **push는 계속 사용자가 요청할 때만** 한다(`CLAUDE.md` §9). 커밋은 작업 단위마다 하되, 중간 상태가 배포되지 않게 push 시점은 사용자가 정한다.
2. **구현은 한 번에 이어서 진행한다**(단계마다 멈춰서 확인받지 않는다). **[사용자: "구현 한번에 이어서 하자"]** 그래도 각 단계가 끝날 때마다 타입 검사·테스트를 돌리고 작업 단위로 커밋한다. 막히거나 시안에 없는 큰 결정이 필요하면 그때 사용자에게 묻는다.
3. **CellCog 이미지는 타이틀 4장 외에는 더 만들지 않는다.** **[사용자: "크레딧 때문에 타이틀에 쓴 거 말고는 더 사용하기 힘들어 보인다"]** (남은 크레딧 약 192.) 따라서 새 일러스트가 필요한 항목은 **기존 도트 그림을 재사용하거나 CSS·SVG로 해결**한다. 이용 조건(약관) 확인은 사용자가 따로 답하지 않았으니 §7의 미확인 가정으로 남긴다.

## 9. 완료 기준

- §3의 모든 결정이 화면에 구현되어 있고, 시안(§10)과 나란히 놓았을 때 같은 구조·같은 테마 느낌이다.
- 360px 모바일과 PC 가운데 패널에서 가로 스크롤·잘림이 없다. 테마 3종 × 글자 3종 × 움직임 3단계가 설정에서 바뀐다.

- 사용자가 직접 플레이로 한 판(15~25분) 확인한다(봇 결과가 사람의 경험은 아니다, `CLAUDE.md` §7).

## 11. 위험과 대응

- **범위가 커서 일정이 늘어난다**(전 화면 + 테마 3종): §5의 순서로 쪼개고 단계마다 확인한다. 테마 B(도트 테두리)와 C는 토큰 위에 얹는 형태라 토대가 잘 잡히면 증분이 작다.
