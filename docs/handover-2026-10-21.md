## 4. 사용자에게 확인이 남은 것 (임시값)

- **업적 상점 가격·효과**(SR 보장권 6토큰, 협상 노하우 10/15/20, 인맥 쌓기 12/20)는 내가 정한 초안이다.
- **구단 등급은 추정**이다. 구단별 공식 재무·팬덤 수치는 못 찾았고, T1 매출 약 905억(커뮤니티 추정)·농심 약 70억 등 방향성만 근거로 썼다. 틀린 구단이 있으면 `market.json`의 `teams`만 고치면 된다.
- 구단 등급 변동의 **운 계수(`luck` 0.45)**: AI 구단 전력이 타고난 강약 비중이 커서 강팀이 급락하는 일은 드물다. 더 자주 몰락하게 하려면 올린다.
- **난이도**: 대회 결과를 '시작 직전' 능력치로 정하면서 성장 반영이 한 턴 늦어져 `rules.growthRate`를 0.28→0.285로 올렸다. 150판 기준 숙련 월드 우승 72~83%, 첫 우승 25.3~26.2세, 26세 이하 첫 우승 AOS 47~49%·FPS 63~65%. AOS 후반(29세 이상) 시즌 우승이 예전 32~37%에서 42~46%로 올랐다. **직접 플레이로 과한지 확인 필요**.
- 인기·명성 보상(`popularityFame`·`prestigeFame`)을 절반으로 줄인 것도 난이도 때문이다.

## 6. 조심할 점 (오늘 겪은 것)

- **테스트 파일을 덮어쓰지 않는다.** `career.test.ts`가 이미 있는 줄 모르고 `Write`로 덮어썼다가 git에서 복구했다. 새 테스트 파일을 만들기 전에 `ls`로 이름을 확인한다(경력 테스트는 `careerRecord.test.ts`).
- **셸에 heredoc을 여러 개 섞지 않는다**(`CLAUDE.md` §11). 파일 수정은 `Write`/`Edit`를 쓰고, 문자열 치환이 많으면 `.scratch_edit.py`를 `Write`로 만들어 한 번 실행하고 지운다. 파일이 CRLF일 수 있어 치환 전에 `\r\n`을 처리한다.
- **노션 `notion-create-pages`는 `parent`와 `pages`를 파라미터로 직접 넘긴다.** JSON 전체를 문자열로 감싸 보내면 파싱 실패가 반복된다(오늘 이걸로 여러 번 실패했다). 작성 전에 기존 행을 조회해 양식(증상·원인·해결·배운 점, 상태 '해결됨')을 맞춘다.
- 난이도 회귀 테스트가 깨지면 기준 숫자를 바꾸지 말고 먼저 리포트(`BALANCE_RUNS=150`)로 원인을 본다. 오늘은 `growthRate` 조정으로 맞췄고, 해외 이적 점검 테스트의 여유만 60판 기본 표본의 잡음을 감안해 0.5→0.8로 넓혔다(150판에서는 기준 안).
- 푸시는 사용자가 요청할 때만, 푸시 전에 `src/data/updates.json`에 인게임 변경이 다 들어 있는지 확인한다.
- 규칙을 바꾸면 `CLAUDE.md`·`docs/design.md`·노션(기획서 본문 포함)을 **함께** 갱신한다. 오늘 기획서 본문 갱신을 한 번 빠뜨려서 사용자가 짚었다.
