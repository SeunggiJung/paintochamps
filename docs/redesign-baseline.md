## 2. 눈으로 확인한 문제

**구조·길이**
- 엔딩 화면이 8,479px(모바일 11화면 분량)이다. 업적·경력·시즌별 기록이 한 열로 쭉 이어진다.
- 시즌 계획 시트는 방침 4·훈련 목록·레슨·장비 4종·시설 9종이 **한 스크롤 시트(3,893px)** 에 들어 있고, 590px 높이 시트 안에서 7화면 넘게 스크롤한다.
- 엔딩 도감은 같은 모양의 잠긴 카드 39장이 한 열로 늘어선다(4,775px).
- 시즌 결산(후반)은 카드 12장, 3,329px이다.
- '1시즌 종료' 중간 화면은 제목·문장·버튼 하나만 있는 거의 빈 화면이다.

**홈 화면**
- 화면 아래에 고정된 턴 바(다음 턴 진행·내 경력·연봉 협상·이적 요청·타이틀로)가 뷰포트의 약 30%를 차지하고, 계획 카드 내용을 가린다(04·08·24).
- 시즌 일정이 10줄 가까이 늘어서 첫 화면 대부분을 쓴다(24).
- 팀 줄의 구단 로고가 아주 작고, 구단 등급 줄(재정·인기·명성 ★)이 길어 두 줄로 꺾인다(23).
- 위 상태 카드(이름·컨디션·돈·명성)와 스크롤 영역의 위계가 약하다.

**타이포·간격**
- 한글이 어색한 곳에서 줄바꿈된다: 타이틀 `프로게 / 이머되기`, 뽑기의 `원하는 등급이 나올 때까 / 지 뽑기` 버튼.
- 타이틀 제목이 위쪽 버튼(밥사주기·소리)과 거의 붙어 있다.
- 시스템 폰트(`system-ui`)만 쓰고 제목·숫자·라벨의 서체 위계가 거의 없다.

**팝업**
- 팝업(`.sheet`)은 가운데 카드지만 높이가 넘치면 안쪽 스크롤이 생기고, 업데이트 로그는 팝업 안에 날짜별 접기와 내용 스크롤이 겹쳐 **스크롤이 두 겹**이다(첫 접속).
- 팝업 뒤 배경이 거의 검정으로 어두워져 어떤 화면 위에 떠 있는지 알기 어렵다.

**색·일관성**
- 다크 남색 단일 테마(`--bg #12141c`, 포인트 `#5b8cff`). 등급색 5개만 별도 정의돼 있고 나머지는 흰색·회색·파랑 위주라 화면마다 강조 방식이 다르다(주황 강조·초록 증가·빨강 감소가 화면별로 따로 쓰임).
- 버튼 종류(주 버튼·보조·고스트·작은 버튼)는 있으나 시각 차이가 작다.

**PC 폭**
- 1280px에서도 약 450px 폭의 한 열이고 양옆이 비어 있다.

## 3. 유지할 것 (사용자 지시)

- 도트·메이플풍 스프라이트와 일러스트(타이틀 장면, 엔딩 장면, 내 방, 계약·중계·광고 연출 등)와 이미지는 **그대로 유지**한다. 나중에 필요하면 따로 바꾼다.
- 엔진·데이터·규칙은 건드리지 않는다.
- 첫 접속 가이드는 `data-guide` 속성으로 요소를 찾으므로, 구조를 바꾸면 단계를 함께 확인한다.

## 4. 재현 방법

1. `npx vite --port 5173`
2. 저장소 비우고 업데이트 로그 숨기기: `localStorage.clear()` 후 `paintochamps:updatelog:hide`에 오늘 날짜(YYYY-MM-DD)를 넣고 새로고침.
3. 초반 화면은 UI로 진행한다(새로 시작 → 능력치 뽑기 → 이 캐릭터로 시작 → 계획 → 다음 턴 진행).
4. 중반·마지막 시즌 상태는 개발 서버의 모듈을 브라우저에서 불러와 만든다: `await import('/src/sim/bot.ts')`로 `playCareer('aos','standard',11,{policy:'skilled',acceptTransfers:true,signAds:true,onTurn})`을 돌리며 `onTurn`에서 원하는 시점의 상태를 복사해 `paintochamps:save`에 JSON으로 저장하고 새로고침 → '이어하기'. 업적 상점·경력 표시용 메타는 `paintochamps:meta`에 `tokens`·`inventory`·`careers`를 넣는다.
5. 마지막 시즌(30세, 마지막 턴 뒤) 상태에서 '시즌 결산 보기 → 커리어 마무리 → 구단을 인수하지 않는다'로 엔딩에 간다.
6. 스크롤 시트 전체는 `.sheet`의 `max-height`·`overflow`를 풀고 전체 페이지로 찍는다.
